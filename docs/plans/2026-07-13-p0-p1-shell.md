# Halo Shell (P0 + P1) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A transparent, always-on-top glass notch pill at the top-center of the primary monitor that springs open/closed on hover — as smooth as Apple's Dynamic Island, with real frosted-desktop glass and no banding.

**Architecture:** A borderless, layered, topmost Win32 tool-window hosts the **system `Windows.UI.Composition`** compositor via `CreateDesktopWindowTarget`. All shapes, glass, and motion are Composition visuals on the compositor thread (refresh-rate synced). Glass = `CreateHostBackdropBrush` + a dark tint; blur/tint are driven by an expand-progress value so the pill is near-opaque black when closed and very glassy when open. No XAML in the shell (XAML Islands come later, only for rich widget content).

**Tech Stack:** C# / .NET 9, `net9.0-windows10.0.19041.0` TFM, `Windows.UI.Composition` (system, via CsWinRT projections), Win32 interop (P/Invoke), Win2D (`Microsoft.Graphics.Win2D`) only for the grain texture.

## Global Constraints

- Platform: Windows only. Target `net9.0-windows10.0.19041.0`, `RuntimeIdentifier win-x64`.
- Language: all identifiers and any UI copy in English.
- **No comments in source** — none. `ponytail:` markers are the only exception during dev and are stripped before any GitHub push. This plan's code blocks are shown with explanatory prose here; the prose does NOT go into the source files.
- Ship self-contained (Windows App Runtime not assumed present) — set at packaging (P6), not now.
- Folder layout per `docs/02-architecture.md`. Solution root: `Halo/`. App project: `src/Halo.App/`.
- One runnable check per non-trivial deterministic unit (geometry math). Visual/interop tasks verify by **build + run + observe** (this is a GUI shell; there is no headless assertion for "the glass looks right").
- Commit after every task.

```csharp
public class NotchGeometryTests
```

- [ ] **Step 2: Run → fails** — `dotnet test` → does not compile (`NotchGeometry` missing).

- [ ] **Step 3: Implement**
```csharp
namespace Halo.Shell;

public static class NotchGeometry
{
    public static (int x, int y, int w, int h) CollapsedRect(int workLeft, int workTop, int workWidth, int collapsedWidth, int collapsedHeight)
        => (workLeft + (workWidth - collapsedWidth) / 2, workTop, collapsedWidth, collapsedHeight);

    public static (int x, int y, int w, int h) ExpandedRect(int workLeft, int workTop, int workWidth, int expandedWidth, int expandedHeight)
        => (workLeft + (workWidth - expandedWidth) / 2, workTop, expandedWidth, expandedHeight);
}
```

- [ ] **Step 4: Run → passes** — `dotnet test` → 2 passed.

- [ ] **Step 5: Position the real window** — in `NotchWindow`, get the primary monitor work area (`SystemParametersInfo SPI_GETWORKAREA` or `GetMonitorInfo` of `MonitorFromWindow`) and size/move to `ExpandedRect` bounds (the window is always the max/expanded size; the pill is drawn inside and animates — the window itself does not resize per frame).

### Task 3: Composition host + static black rounded pill

**Files:**
- Create: `src/Halo.App/Interop/CompositionInterop.cs`, `src/Halo.App/Shell/CompositionHost.cs`, `src/Halo.App/Rendering/GlassPill.cs`
- Modify: `Program.cs` (create host after window)

**Interfaces:**
- Consumes: `NotchWindow.Hwnd`.
- Produces: `CompositionHost(IntPtr hwnd)` exposing `Compositor Compositor` and `ContainerVisual Root`; `GlassPill` exposing a `Visual` and `void SetSize(float w, float h)`, `void SetCornerRadius(float r)`.

- [ ] **Step 1: DispatcherQueue + interop declarations**

`src/Halo.App/Interop/CompositionInterop.cs` — P/Invoke `CreateDispatcherQueueController` (CoreMessaging.dll) and the COM interface:
```csharp
[System.Runtime.InteropServices.ComImport]
[System.Runtime.InteropServices.Guid("29E691FA-4567-4DCA-B319-D0F207EB6807")]
[System.Runtime.InteropServices.InterfaceType(System.Runtime.InteropServices.ComInterfaceType.InterfaceIsIUnknown)]
interface ICompositorDesktopInterop
{
    void CreateDesktopWindowTarget(nint hwnd, bool isTopmost, out nint result);
    void EnsureOnThread(int threadId);
}
```
Create a `DispatcherQueueController` on the current thread BEFORE `new Compositor()` (the compositor requires a dispatcher queue on the thread).

- [ ] **Step 2: CompositionHost wires the target**
```csharp
var compositor = new Windows.UI.Composition.Compositor();
var interop = compositor.As<ICompositorDesktopInterop>();
interop.CreateDesktopWindowTarget(hwnd, true, out var raw);
var target = Windows.UI.Composition.Desktop.DesktopWindowTarget.FromAbi(raw);
var root = compositor.CreateContainerVisual();
root.RelativeSizeAdjustment = System.Numerics.Vector2.One;
target.Root = root;
```
Keep `target` referenced (do not let it GC).

- [ ] **Step 3: GlassPill — static black rounded sprite**

For now a plain dark fill (glass comes in Task 4). Use a `SpriteVisual` with a `CompositionColorBrush` (near-black, alpha ~0.85), sized to the collapsed pill, centered in `root`, and a rounded-corner **geometric clip**:
```csharp
var pill = compositor.CreateSpriteVisual();
pill.Brush = compositor.CreateColorBrush(Windows.UI.Color.FromArgb(0xD9, 0x0A, 0x0A, 0x0A));
pill.AnchorPoint = new System.Numerics.Vector2(0.5f, 0f);
pill.RelativeOffsetAdjustment = new System.Numerics.Vector3(0.5f, 0f, 0f);
```
Rounded corners: build a `CompositionRoundedRectangleGeometry`, wrap in a `CompositionGeometricClip`, assign `pill.Clip`. Expose `SetSize` (sets `pill.Size` and the geometry size) and `SetCornerRadius`.

- [ ] **Step 4: Build + run + observe**

Run: `dotnet run --project src/Halo.App`
Expected: a **black rounded pill** sits at the top-center of the primary monitor, everything around it fully transparent (desktop shows through). This proves the layered-window + Composition foundation. If the whole window is black/gray, the `WS_EX_NOREDIRECTIONBITMAP` / transparency path is wrong — fix here before moving on.

```bash
git add src && git commit -m "P0: system-Composition host + static glass pill (transparency proven)"
```

### Task 4: Real glass (host backdrop blur + tint + top highlight)

**Files:**
- Modify: `src/Halo.App/Rendering/GlassPill.cs`

**Interfaces:**
- Produces: `GlassPill.SetGlass(float blurAmount, float tintOpacity)` — sets how frosted vs. how opaque-dark the pill is.

- [ ] **Step 1: Host backdrop brush**

`CreateHostBackdropBrush()` samples the blurred desktop behind the window. Composite it with a dark tint using an effect graph (`Microsoft.Graphics.Canvas.Effects` is NOT needed here; use `CompositionEffectBrush` with a `ColorSourceEffect` over a `CompositionEffectSourceParameter("backdrop")` blended by opacity). Assign the resulting brush to the pill sprite. Add a thin 1px top inner highlight (`CompositionColorBrush` white ~0.12 alpha on a 1px sprite along the top edge).

- [ ] **Step 2: SetGlass**

Expose `SetGlass(blurAmount, tintOpacity)`:
- Host backdrop blur radius is fixed by the OS brush, so simulate "less glass" by raising the tint's opacity toward 1 (near-opaque black) and lower it toward ~0.25 for full glass. `blurAmount` is reserved for the P1 interpolation (may map to a secondary Gaussian if host blur is insufficient).

- [ ] **Step 3: Build + run + observe**

Expected: the pill now shows a **frosted version of the desktop** behind it with a dark tint; the top edge has a subtle highlight. Move a bright window behind it — the glass should pick up the color softly.

- [ ] **Step 4: Commit**
```bash
git add src && git commit -m "P1: host-backdrop glass + tint + top highlight"
```

- [ ] **Step 1: Hit-testing in WndProc**

Handle `WM_MOUSEMOVE` + `WM_MOUSELEAVE` (use `TrackMouseEvent`). Because the window spans the full expanded rect but the collapsed pill is small, compute whether the pointer is within the **current** pill bounds; the transparent margin should pass clicks through — set the window hit-test so only the pill area is opaque to input by handling `WM_NCHITTEST`/returning `HTTRANSPARENT` outside the pill rect (or use `WS_EX_LAYERED` alpha hit-testing). - [ ] **Step 2: State transitions**

`Idle → Expanded` on pointer inside; `Expanded → Idle` on pointer left; `RequestAttention()` sets `Peek` if currently `Idle`. Raise `StateChanged`.

- [ ] **Step 3: Build + run + observe**

### Task 6: Spring expand/collapse

**Files:**
- Create: `src/Halo.App/Rendering/Springs.cs`
- Modify: `src/Halo.App/Shell/NotchController.cs` (drive springs on StateChanged), `GlassPill.cs`

**Interfaces:**
- Produces: `Springs.SizeSpring(Compositor, Vector2 to)`, `Springs.ScalarSpring(Compositor, float to)` returning configured `SpringVector3/ScalarNaturalMotionAnimation`; a shared `DampingRatio`/`Period` pair (the tuning knob).

- [ ] **Step 1: Spring helpers**

Create `SpringVector3NaturalMotionAnimation` (for size) and `ScalarKeyFrameAnimation`/`SpringScalarNaturalMotionAnimation` (for corner radius and expand-progress). Start with `DampingRatio = 0.75f`, `Period = TimeSpan.FromMilliseconds(45)` and expose them as constants to tune. `ponytail: these two numbers ARE the feel; expect to hand-tune on the 144Hz panel, don't hardcode-and-forget.`

- [ ] **Step 2: Drive on state change**

On `StateChanged`, animate the pill `Size` between collapsed and expanded rects and corner radius (collapsed radius = height/2 for a full pill; expanded radius ~28). Use `StartAnimation("Size", ...)`. Also animate a shared scalar `expandProgress` 0→1 used next task.

- [ ] **Step 3: Build + run + observe (the make-or-break check)**

Expected: hover → the pill **springs** open with a slight overshoot and settles; leave → springs closed. Verify it stays smooth at 60/120/144Hz (Task 4 in `docs/04-rendering-glass.md`). If it stutters, confirm animations are Composition (compositor-thread), not driven from a timer.

- [ ] **Step 4: Commit**
```bash
git add src && git commit -m "P1: spring expand/collapse on the compositor thread"
```

### Task 7: Glass interpolation + grain (kill banding)

**Files:**
- Create: `src/Halo.App/Rendering/Grain.cs`
- Modify: `GlassPill.cs`, `NotchController.cs`

**Interfaces:**
- Consumes: the shared `expandProgress` scalar from Task 6.
- Produces: `Grain.CreateBrush(Compositor)` — a tiling low-opacity noise brush.

- [ ] **Step 1: Bind glass to expandProgress**

With an `ExpressionAnimation`, drive tint opacity from `expandProgress`: `Lerp(0.9, 0.25, expandProgress)` (near-opaque black when collapsed → very glassy when expanded). Bind it so glass thickens exactly as the size spring runs — no separate timer.

- [ ] **Step 2: Grain layer**

`Grain.cs`: render a small (e.g. 128x128) noise texture once with Win2D (`Microsoft.Graphics.Win2D`) onto a `CompositionDrawingSurface`, wrap as a `CompositionSurfaceBrush` with `Stretch = None` and wrapping, put it on a sprite above the glass at ~3–5% opacity. This dithers the smooth blur gradient so there is no LED-like banding.

- [ ] **Step 3: Build + run + observe**

Expected: expanding shows the glass getting clearly more transparent/frosted; collapsed reads as a clean dark Apple pill; the glass gradient has fine grain and **no visible banding**. Compare side-by-side with DynamicWin — should look markedly cleaner.

- [ ] **Step 4: Commit**
```bash
git add src && git commit -m "P1: expand-bound glass interpolation + grain (no banding)"
```
